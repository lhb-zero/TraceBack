## 决策 1：向量数据库选择 ChromaDB

- **背景**：需要一个向量存储方案，文档量预计 <10 万条，内部部署
- **选项**：
  - 方案 A：Pinecone — 全托管、性能好，但收费且数据出境
  - 方案 B：ChromaDB — 本地嵌入式、零运维、Python 原生支持
  - 方案 C：Milvus — 功能强大但部署复杂，适合百万级数据
- **决定**：选 ChromaDB。数据量小、内部使用、不想引入额外运维负担
- **后果**：开发体验极好，pip install 即用。但并发性能有限，如果用户量增长需要迁移

## 决策 2：Chunk 策略从固定切分改为语义切分

- **背景**：初版用固定 512 token 切分，发现中文文档经常被切断语义
- **选项**：
  - 方案 A：固定 token 切分 + 重叠窗口 — 简单但语义碎片化
  - 方案 B：按段落/标题结构切分 — 保留语义完整性
  - 方案 C：递归切分（LangChain RecursiveCharacterTextSplitter）— 折中
- **决定**：方案 B + 重叠窗口。先用 jieba 识别段落边界，再按段落切分
- **后果**：召回率提升约 20%，但切分逻辑变复杂，需要针对不同文档格式适配
