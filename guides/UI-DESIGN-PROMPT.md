# 项目复盘系统 — UI 设计提示词

> 本文档用于喂给 UI 设计 AI 工具（v0.dev / Figma AI / Galileo AI 等），生成前端页面设计稿。
> 可整体使用，也可按页面拆分单独投喂。

---

## 一、项目背景（给设计工具的上下文）

这是一个**个人开发者的项目复盘系统**。用户是一名从 Java 后端转型 AI 应用开发的程序员，每做完一个项目（或项目的一个阶段），会在这个系统里归档一份结构化复盘。系统同时收录日常"踩坑记录"（技术问题的排查与解决过程）。

**核心使用场景：**
- 做完项目后，快速归档复盘（内容主要由 AI 生成，人工补充）
- 几个月后回来翻阅，5 分钟内回忆起项目全貌
- 遇到类似问题时，快速搜索历史踩坑记录
- 浏览自己的成长轨迹（时间线、标签聚合）

**用户：** 仅开发者本人，不需要考虑公开访问、多用户、权限等场景。

**技术实现：** Next.js SSG + Tailwind CSS + MDX，中文界面。

## 二、设计方向

### 风格关键词
开发者的个人档案馆、代码仓库美学、时间线驱动、信息密度适中、深夜可读

### 具体要求

1. **整体氛围**：像一本开发者的工程日志/档案库，不是企业级 SaaS 后台，也不是花哨的营销页面。安静、专注、有秩序感，但细节处有温度（比如状态色、里程碑节点动效）。

2. **配色**：深色主题为主（开发者深夜回顾场景）。避免纯黑+单一霓虹色的刻板搭配，使用有层次的深色调（如深蓝灰、墨绿灰）+ 2-3 个功能色（状态色：进行中/已完成/已废弃 各一色）。

3. **字体**：标题/数据用有辨识度的字体（可用等宽字体做元数据、日期、标签的展示，呼应代码感），正文用清晰易读的中文字体。形成"代码感元数据 + 舒适正文"的对比。

4. **布局**：
   - 左侧固定导航栏（窄，图标+文字）或顶部导航均可，但必须包含：首页、复盘、踩坑、标签、搜索 五个入口
   - 内容区宽度适中（阅读舒适），不要太宽的通栏
   - 信息层级清晰：元数据（日期、状态、标签）用小型等宽字体，标题大而醒目，正文舒适行高

5. **动效**：
   - 时间线节点 hover 时展开摘要
   - 页面切换/列表加载有轻量过渡
   - 卡片 hover 有微妙浮起感
   - 不要过度动画，保持工具感

6. **避免**：
   - 企业后台感（不要侧边栏+面包屑+表格的经典 admin 布局）
   - 营销页感（不要大 hero banner + CTA 按钮）
   - 卡片瀑布流堆砌
   - 圆角过大的泡泡感

## 四、页面详细设计

### 页面 1：首页（仪表盘 + 时间线）

**页面结构（从上到下）：**

**① 统计条**（一行，4-5 个数字）：
```
项目总数: 12    进行中: 2    已完成: 9    已废弃: 1    踩坑记录: 34    待回顾: 3
```
- 数字大而醒目（等宽字体），标签小而淡
- 不需要图表，纯数字即可
- "待回顾"数字如有值，用醒目色提示

**② 待回顾提醒区**（仅当有待回顾项时显示）：
```
⏰ 待回顾
┌────────────────────────────────────────────────┐
│ RAG 智能客服项目 — 向量检索调优（标记于3个月前）    │
│ 当时理解度：2/5 · 标记原因：HNSW 参数没吃透       │
│                              [去回顾 →]          │
└────────────────────────────────────────────────┘
```
- 列表形式，每条一行，点击跳转详情
- 视觉上与正常内容有区分（如左侧色条）

**③ 时间线**（页面主体）：
- 纵向时间线，左侧是时间轴（年 > 月），右侧是内容条目
- 条目类型混合：项目复盘（卡片样式）和踩坑记录（紧凑行样式），通过图标/颜色区分
- 项目复盘条目示例：

```
2026-08 ●────────────────────────────────────────
         │ RAG 智能客服项目                    [已完成]
         │ 基于 LangChain + ChromaDB 的企业知识库问答系统
         │ #python #langchain #rag #chromadb
         │ 里程碑 ×3 · 理解度 4/5 · 2026-06 ~ 2026-08
```

- 踩坑记录条目示例（更紧凑）：

```
2026-08 ○── CUDA 12.x 安装后 nvcc not found    [已解决] #cuda #环境配置
```

- 时间线节点：项目用实心圆，踩坑用空心圆
- hover 条目时显示摘要浮层或展开

### 页面 2：复盘列表页

**页面结构：**

**① 页头**：标题"项目复盘" + 筛选栏

**② 筛选栏**（一行）：
- 状态筛选：全部 / 进行中 / 已完成 / 已废弃（pill 按钮组）
- 标签筛选：下拉或多选 tag
- 排序：最新优先 / 最早优先

**③ 项目列表**：
每个项目一行/一卡片，包含：

```
┌─────────────────────────────────────────────────────┐
│ RAG 智能客服项目                        [已完成]      │
│ 基于 LangChain + ChromaDB 的企业知识库问答系统        │
│                                                     │
│ #python #langchain #rag    2026-06 ~ 2026-08        │
│ 里程碑 3 条 · 理解度 ●●●●○ · 踩坑关联 5 条           │
│                                                     │
│ github.com/user/rag-chatbot ↗                       │
└─────────────────────────────────────────────────────┘
```

- 状态徽章颜色：进行中=蓝/绿、已完成=绿/青、已废弃=灰/红
- 理解度用 5 个点/格表示（1-5分）
- 列表间距舒适，不拥挤

### 页面 3：复盘详情页（最复杂的页面）

**页面结构：**

**① 项目头部区**：
```
← 返回列表

RAG 智能客服项目                          [已完成]
2026-06 ~ 2026-08 · 创建于 2026-08-01 · 理解度 4/5

#python #langchain #rag #chromadb

📎 github.com/user/rag-chatbot ↗
```

**② GitHub 关联区**（如有 commits/PRs）：
```
关键 Commits
  ● abc1234 — 完成核心 RAG 管道           2026-07-02 ↗
  ● def5678 — 重构 prompt 模板管理         2026-07-15 ↗
  ● 9ab0123 — 接入评估框架                2026-07-28 ↗

PRs
  #12 优化 chunk 分割策略 ↗
```
- commits 以小型时间线展示，hash 用等宽字体
- 所有链接可点击跳转 GitHub

**③ 里程碑导航**（核心交互）：
```
里程碑时间线（横向或纵向）：
  ● 2026-06-15 基础架构搭建
  ● 2026-07-10 RAG 管道完成        ← 当前选中
  ● 2026-08-01 项目收尾与整体回顾
```
- 点击切换显示对应里程碑的正文内容
- 当前节点高亮
- 如果项目没有里程碑（小项目），此区域不显示，直接展示 index.mdx 正文

**④ 正文内容区**（MDX 渲染）：
- 五维度结构，每个维度是一个 section：
  - 项目概述
  - 技术要点
  - AI 协作记录
  - 踩坑与解决
  - 我学到了什么
- 正文排版：舒适的行高（1.8）、段落间距、代码块高亮（深色代码块 + 语法着色）
- 引用块用于"理解验证"类内容（自己的话解释核心逻辑）
- 二级标题有视觉锚点（如左侧色条或编号）

**⑤ 子文档导航**（如有 decisions.mdx / ai-collaboration.mdx）：
```
📄 技术决策记录 (3条)
📄 AI 协作详情 (6个片段)
```
- 点击展开或跳转对应内容

**⑥ 关联踩坑**（底部）：
```
本项目相关踩坑记录（5）
  · CUDA 12.x 安装后 nvcc not found        2026-06-16
  · ChromaDB 持久化路径权限问题             2026-06-20
  · ...                        [查看全部 →]
```

### 页面 4：踩坑列表页

**页面结构：**

**① 页头**：标题"踩坑记录" + 统计（总数 / 已解决 / 未解决）

**② 筛选栏**：
- 状态：全部 / 已解决 / 未解决
- 严重程度：全部 / low / medium / high
- 标签：下拉多选
- 关联项目：下拉（可选某个项目，只看该项目的坑）

**③ 列表**（比复盘列表更紧凑，偏表格式但不呆板）：
```
┌──────────────────────────────────────────────────────────┐
│ ⚠ CUDA 12.x 安装后 nvcc not found                        │
│   2026-08-01 · #cuda #gpu #环境配置 · severity: high      │
│   关联项目：RAG 智能客服 · ✅ 已解决                        │
├──────────────────────────────────────────────────────────┤
│ ⚠ Docker 容器内无法访问宿主机 GPU                          │
│   2026-07-20 · #docker #nvidia · severity: medium         │
│   关联项目：无 · ✅ 已解决                                 │
└──────────────────────────────────────────────────────────┘
```

- severity 用颜色区分：high=红/橙、medium=黄、low=灰
- 未解决的条目有醒目标记（如左侧橙色条）

### 页面 5：踩坑详情页

**页面结构：**

```
← 返回踩坑列表

⚠ CUDA 12.x 安装后 nvcc not found        [已解决] [severity: high]
2026-08-01 · #cuda #gpu #windows #环境配置
关联项目：RAG 智能客服 ↗

────────────────────────────────────────

## 问题现象
执行 nvcc --version 报错 "nvcc not found"，但 CUDA Toolkit 已安装...

## 环境
- OS: Windows 11 25H2
- CUDA: 12.4
- GPU: RTX 4060

## 排查过程
1. 检查环境变量 PATH → 缺少 nvcc 路径
2. 添加后仍报错 → 发现安装了多个 CUDA 版本冲突
3. ...

## 根因
多版本 CUDA 共存时，PATH 指向了旧版本的空目录...

## 解决方案
（代码块 + 步骤列表）

## 预防/备忘
以后安装 CUDA 前先卸载旧版本，装完立即验证 nvcc --version
```

- 正文渲染与复盘详情一致
- 代码块需语法高亮
- "解决方案" section 可以视觉上稍加强调（毕竟是搜索后最想看的部分）

- 分两组显示：项目复盘 / 踩坑记录
- 复用列表页的条目样式

- 结果按类型分组
- 无结果时显示空状态提示

## 五、通用组件规格

| 组件 | 说明 |
|------|------|
| 状态徽章 | 进行中(冷色) / 已完成(暖绿) / 已废弃(灰) / 已解决(绿) / 未解决(橙) |
| 标签 Tag | 小型圆角矩形，等宽字体，# 前缀，hover 可点击跳转标签页 |
| 理解度 | 5 格/点，填充数 = 分数，等宽风格 |
| GitHub 链接 | 带 GitHub 图标 + ↗ 外链标记，等宽字体显示 URL |
| Commit 行 | hash(等宽,短) + 说明 + 日期 + 外链图标 |
| 时间线节点 | 项目=实心圆，踩坑=空心圆，当前=高亮放大 |
| 代码块 | 深色底 + 语法高亮 + 语言标签 + 可选复制按钮 |
| 空状态 | 简洁插画或文字提示（如"还没有复盘记录，去做个项目吧"） |
